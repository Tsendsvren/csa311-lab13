# SELF-EVALUATION.md

## 1. Шалгалт өнөөдөр болбол энэ кодыг өөрөө бичиж чадах уу?

**Хэсэгчлэн** - тайлбартай:

**Чаддаг зүйлс:**
- Express router, middleware бүтэц - лекц болон AI-тай хамт сурсан тул ойлгосон
- Repository pattern - SQL query-г тусгаарлах зарчмыг ойлгосон
- Тест бичих - `supertest` + `jest` хэрхэн ажилладгийг практикт мэдэрсэн
- SQLite schema, constraint - бие даан бичиж чадна

**Хэцүү байх зүйлс:**
- `better-sqlite3` transaction-ийн synchronous API-г синтаксын нарийн ширийнийг дурсахад хэцүү байж магадгүй
- TypeScript generic (`ApiResponse<T>`) бүх нарийн ширийнийг дурсах
- `ts-jest` preset тохируулах - баримтжуулалт харах хэрэгтэй болно

**Дүгнэлт:** Архитектур болон логикийг тайлбарлах чадвар байна. Зарим syntax-ийг хайж олох хэрэгтэй болно - гэхдээ энэ мэргэжлийн хэм хэмжээ, AI байхгүй ч баримтжуулалт ашиглаж бичиж чадна.

## 2. Дахин хийнэ гэвэл юуг өөрөөр хийх вэ?

**1. AI session log илүү эрт, илүү нарийн хадгалах**
Хамгийн анхны session-уудаа хадгалахаа мартаж, сүүлд санаж байсан зүйлсийг бичсэн. Дараагийн удаа: conversation дуусмагц товчилж хадгалах.

**2. Git commit-ийн дэс дараалал илүү нарийн төлөвлөх**
Зарим commit хэт том (нэг commit-д олон файл нэмсэн тохиолдол байсан). "Нэг логик өөрчлөлт - нэг commit" зарчмыг чанд баримтлах.

**3. AI-д илүү нарийн prompt өгөх**
"TypeScript repository pattern бич" гэхийн оронд "Mini library системийн BookRepository бич, better-sqlite3 synchronous API ашиглах, findAll search parameter-тэй байх" гэж нарийвчлах. Нарийн prompt → нарийн хариу.

**4. Frontend-д илүү цаг зарцуулах**
Backend дуусаад frontend-д цаг дутсан - Swagger UI байсан ч энгийн HTML дашбоард нэмэлт үнэ цэнэ нэмэх байсан.

## 3. Энэ туршлагаас юу сурсан бэ?

**Техникийн талаар:**
- Repository pattern нь controller-д SQL байхгүй болгодог тул тест бичихэд маш хялбар болдог - энэ практик дадлагаар мэдэрсэн
- `better-sqlite3` synchronous API нь async/await complexity-г арилгадаг - жижиг API-д энэ сонголт зөв байсан
- In-memory SQLite тестэд ашиглах хандлага - тест бүр clean state-тай эхэлдэг

**AI-тай ажиллах талаар:**
- "Verify, don't trust" зарчим практикт юу гэсэн үг болохыг ойлгосон (CASCADE DELETE жишээ)
- AI draft хурдан гаргадаг, гэхдээ business context мэддэггүй  "идэвхгүй гишүүн түрээсэлж болохгүй" гэх бизнес дүрмийг AI санал болгоогүй, өөрөө нэмсэн
- AI session log хадгалах нь дараа нь "яагаад тэр шийдвэр гаргасан" гэдгийг ойлгоход тусалдаг

**Мэргэжлийн талаар:**
- Кодлогчийн үүрэг "бичих"-ээс "дизайн + верификаци" руу шилжиж байгааг бодитоор мэдэрсэн
- ADR бичих - шийдвэрийн контекстийг хадгалах нь баг болон өөртөө ч ач тустай
- Conventional Commits format нь git history-г унших, debug хийхэд хэр хэрэгтэй болохыг ойлгосон
